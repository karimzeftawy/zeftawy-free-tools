Python guide — TLS

Check TLS certificate expiry without disabling verification

A useful expiry check should still authenticate the server. Avoid disabling hostname or CA validation for ordinary operational checks.

Verify the handshake

import ssl
import socket
host = "example.com"
ctx = ssl.create_default_context()
with socket.create_connection((host, 443), timeout=5) as sock:
    with ctx.wrap_socket(sock, server_hostname=host) as tls:
        cert = tls.getpeercert()
print(cert["notAfter"])

Python's default TLS context verifies the CA chain and hostname. server_hostname supplies the intended name (and SNI).

Calculate remaining days in UTC

from datetime import datetime, timezone
import ssl
seconds = ssl.cert_time_to_seconds(cert["notAfter"])
expiration = datetime.fromtimestamp(seconds, timezone.utc)
days = (expiration - datetime.now(timezone.utc)).total_seconds()/86400
print(f"Days remaining: {days:.1f}")

What if the certificate is expired?

An expired, self-signed or hostname-mismatched certificate typically fails validation before Python returns verified metadata. Treat this as a validation error, not as a success. Don't silently turn off TLS verification to make a monitoring dashboard look healthy.

This example is one manual check, not a scheduled monitoring or vulnerability scanning service. Bundled offline data is synthetic and clearly marked as such.
