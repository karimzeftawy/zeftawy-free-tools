DNS resolution is not a TCP health check

A hostname can resolve perfectly while its service is down. Use separate tests for name resolution, transport connectivity and application health.

Resolve the hostname

import socket
records = socket.getaddrinfo("example.com", None, type=socket.SOCK_STREAM)
addresses = sorted({item[4][0] for item in records})
print(addresses)

Results can vary with IPv4/IPv6, resolver configuration, network location and time. A successful response gives addresses, not proof of service health.

Test one TCP port

try:
    with socket.create_connection(("example.com",443), timeout=3):
        print("TCP connected")
except OSError as exc:
    print(f"TCP failed: {exc}")

Connection refusal suggests no accepting listener or an active reject. Timeouts may result from filtering, packet loss, routing issues or an unresponsive host. A successful TCP handshake still does not validate the HTTP service or TLS certificate.

Only test systems you manage or have permission to assess. This is a single chosen TCP-port check, not broad scanning.
